Merged the reviewed PR #14 fixes into this branch without rewriting its published history. The following findings are corrected in the follow-up commits.

1. **P2: interruption leaked live synthetic infrastructure.** Normal browser/load runs had no SIGINT/SIGTERM cleanup handler. Terminating the original load runner left its application and database running; an original-code probe reproduced this and then removed only its synthetic resources. The harness now stops managed subprocess groups, app and worker, closes the proxy/connections, and removes its owned database/volume/directory. Cleanup is idempotent, handles interruption during creation, and attempts every resource even after a cleanup error. Docker commands and the browser subprocess also have explicit deadlines. A committed lifecycle test waits for an actual successful worker heartbeat, interrupts a running subprocess with a descendant, and verifies removal of the database/directory, closure of the application port and termination of the descendant.

2. **P2: financial acceptance could pass when measured mints never happened.** Counting HTTP 200 responses, fills and a clean reconciliation does not prove the expected mint writes occurred. Fault injection replaced each measured mint response with HTTP 200 without writing anything: the original script still passed with 1,060 fills and clean reconciliation. The reviewed script rejects this same fault because it observes only ten fixture mints and 1,000 shares per outcome. A passing run now requires all 70 active-market mint operations and exactly 1,060 shares of each outcome, in addition to the existing fill, payout, reservation and reconciliation gates. Failed requests now retain their timing samples too.

3. **P2: subsecond clock movement could invalidate the claimed lock-wait bound.** The original maximum sample gap used database wall time, while clock movement below one second was accepted independently of the 500 ms lock threshold. A backward clock step could therefore hide a relevant wait. The bound now adds the maximum monotonic sample gap and the full observed clock-offset range to the maximum observed lock age. Unit cases cover missed observations, a 500 ms clock step, opposite offsets and invalid measurement sequences. The agreed 500 ms and one-second limits were preserved.

4. **P2: mobile acceptance did not exercise touch actions.** Enabling a touch-capable mobile context while using Playwright mouse clicks does not test touch interaction. The mobile workflow now uses taps, including checkboxes, and requires observed touchstart events. The full mobile flow, axe checks and reflow checks pass with those actual touch actions. The keyboard and desktop workflows pass as well.

The pre-existing red CI run was also investigated: its first backup archive test exceeded five seconds while deeply comparing a one-megabyte Buffer. PR #14 now uses an exact native byte comparison, keeping the same data size and timeout. Both PR #14 GitHub verification jobs passed after this fix, and PR #15 inherits it. No acceptance threshold was relaxed.
